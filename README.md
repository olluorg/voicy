# voicy

Локальный речевой сервер: синтез и распознавание речи с **API, совместимым
с аудио-частью OpenAI**. Запускается одной командой, работает на своей машине,
ключей не требует — потому что их нет.

```bash
curl -O https://raw.githubusercontent.com/olluorg/voicy/master/compose.yml
docker compose up -d
```

Консоль — `http://localhost:8080`, API — `http://localhost:8080/v1`.
Подробности — [`server/README.md`](server/README.md).

Из командной строки — без HTTP и без зависимостей:

```bash
./voicy up                          # поднять сервер и прогреть модели
./voicy say "текст" out.opus        # синтез
./voicy hear out.opus               # распознавание
```

Docker при этом не обязателен: без него `up` поднимает сервер из исходников,
а `--install` доставляет зависимости в `.venv` рядом.

Работающему здесь код-агенту достаточно [`AGENTS.md`](AGENTS.md).

Под этим лежит исследование: **как озвучивать инженерные тексты** — те, что напичканы кодом,
нотацией, аббревиатурами и терминами, — так, чтобы их можно было усваивать на слух.

Повод: тренажёру подготовки к собеседованиям bkdojo нужен аудиорежим,
чтобы заниматься на прогулке. Быстро выяснилось, что задача не сводится к «взять TTS
и скормить ему текст со страницы».

## Главный результат

Полностью локальный конвейер, дающий речь **на уровне учебной нормы темпа при
сохранённой разборчивости**:

| Метрика | Начало | Итог |
|---|---|---|
| CER (потеря символов при обратном распознавании) | 25.3% | **0.8%** |
| Темп | 160 слов/мин | **114 слов/мин** — темп чтеца в референсе |
| Паузы | обрыв в цифровой ноль | ни одной вставленной, все модельные |
| Слитность фразы | четыре куска вместо одного вдоха | ноль разрывов внутри фразы |
| Тишина в записи | — | 1.8% против 20% у прежнего движка |
| Постобработка | растяжение ×0.66 | не применяется |
| Текст | озвученный листинг | объяснение смысла |

Слушать и читать разбор: **https://olluorg.github.io/voicy** — интерактивная статья
со всеми замерами, графиками и аудио. Локальная копия — [`article/index.html`](article/index.html).

## Что выяснилось (кратко)

1. **Метрика важнее слуха.** Пока «съедает буквы» оставалось впечатлением, спорить
   было не о чем. Прогон синтеза обратно через ASR и подсчёт CER превратил это
   в число и сразу расставил движки по местам.
2. **Подготовка текста решает больше, чем выбор движка.** Транслитерация нотации
   (`List<? extends Number>` → «лист вайлдкард экстендс Намбер») — всё ещё листинг,
   просто озвученный. Нужно переписывать в объяснение.
3. **Ручка `speed` у диффузионной модели — ловушка.** Замедление ею роняет
   разборчивость вчетверо.
4. **Референс определяет почти всё у zero-shot моделей** — и тембр, и артикуляцию,
   и темп, и характер пауз. Разброс по CER между образцами голоса — от 1.0% до 21.9%
   при прочих равных.
5. **Референс режется по границам фраз, а не по таймеру.** Модель получает его
   транскрипт дословно: обрубленный текст портит каждый синтезируемый сегмент.
   Одна только чистая перенарезка дала 7.3% → 1.0%.
6. **Если параметр приходится подкручивать всё сильнее — источник выше по конвейеру.**
   Затухание уползало с 45 мс к 8, растяжение с ×0.9 к ×0.66; оба раза чинилось
   не то место.
7. **Свойства референса нельзя оптимизировать по одному.** Темп, слитность
   и разборчивость независимы: самый слитный чтец дал CER 18.8%, самый
   разборчивый читал слишком быстро. Отбор — по трём измерениям сразу.
8. **Конвейер в итоге схлопнулся до `текст → синтез одним проходом`.** Всё, что
   добавлялось по дороге — вставленные паузы, фон комнаты, затухания, разброс
   длительностей, растяжение, разбивка на реплики — было компенсацией плохо
   выбранного референса и ушло вместе с ним.
9. **Тембр принадлежит чтецу, манера — отрывку.** У одного и того же чтеца
   плотность пауз гуляет от 6.7 до 20 в минуту. Голос выбирает человек,
   отрывок внутри его записи выбирает скрипт по прямой пробе на контрольной фразе.
10. **Текст пишется короткими предложениями без внутренней пунктуации.** Запятая
   читается моделью как повод остановиться, придаточное заставляет ухо удерживать
   начало фразы до конца. Среднее упало с 7.6 до 5.2 слов, запятые — с 26 до нуля.
11. **Смена архитектуры дала больше, чем десять раундов настройки.** Рваность речи
   оказалась свойством F5/DiT: три разных чекпойнта ESpeech дали одинаковые числа,
   а Qwen3-TTS на том же референсе — 38 пауз вместо 120 и 1.8% тишины вместо 20%.
12. **Внешний рейтинг — снимок на дату.** Лидерборд, на который опирался отбор,
   не обновлялся год; всё вышедшее позже отсутствовало в нём по построению.
13. **Ударениями в Qwen3-TTS управляют текстом, а не разметкой.** Модель обучалась
   без знаков ударения: `+` она произносит вслух, диакритика коверкает слово.
   Работает переписывание омографов; ЗАГЛАВНЫЕ — единственная нотация, не портящая
   текст.
14. **Прежде чем верить измерению, проверь измеритель.** Детектор ударений показал
   61% ошибок у синтеза — и 70% у живой человеческой речи, где ударения верны
   по определению. Его числа выброшены.
15. **Ударение определяется сопоставлением с эталоном, а не поиском в сигнале.**
   Silero принимает заданную позицию ударения, поэтому слово синтезируется
   с ударением на каждом слоге — это эталоны, а кандидат сравнивается по форме
   контура громкости. Межголосовая валидация: 77% против 25% у случайного.
16. **Словарь произношений собирается без человека.** 79 терминов, все
   подтверждены автоматически обратным распознаванием; написание аббревиатур
   выводится правилом из самого термина, что убрало целый класс опечаток.

## Как запустить

**Готовый образ, без выкачивания репозитория:**

```bash
docker run --gpus all -p 8080:8080 \
  -v voicy-models:/cache \
  -v voicy-voices:/app/server/voices \
  ghcr.io/olluorg/voicy:latest
```

или через `compose.yml` — он добавляет тома, перезапуск и проброс GPU.

Первый запуск скачивает веса моделей, около пяти гигабайт, в том `models`;
дальше они берутся оттуда и пересборку образа переживают.

**Без GPU** — добавьте `-e FORCE_CPU=1`. Работает, но заметно медленнее.

С видеокартой синтез быстрее реального времени: ×1.5 на RTX 3080, минута речи
примерно за 40 секунд. Серверу целиком нужно около 7.4 ГБ видеопамяти,
с распознаванием в int8 — около 6.4 ГБ. Разбор и цифры — в разделе «Системные
требования и скорость» [`server/README.md`](server/README.md).

**Из исходников** — см. [`server/README.md`](server/README.md).

## Структура

```
voicy         однострочный доступ к серверу из командной строки
AGENTS.md     краткая инструкция для код-агентов
data/         исходные тексты экспериментов (образцы, партитура реплик)
scripts/      всё, чем генерировалось и мерилось
results/      сырые замеры каждого прогона (json)
experiments/  описание итераций: что меняли, что получили
docs/adr/     архитектурные решения и их обоснование
docs/blog/    хронология: как шло исследование, включая тупики
article/      итоговая интерактивная статья + всё аудио (opus)
server/       речевой сервер: OpenAI-совместимое API и веб-консоль
```

## Как воспроизвести

Нужны Python 3.11, ffmpeg, NVIDIA GPU (для ESpeech/Whisper; Piper/Silero/Vosk
работают на CPU).

```bash
uv venv --python 3.11 f5-venv
uv pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu128
uv pip install f5-tts ruaccent soundfile huggingface_hub faster-whisper jiwer

# при медленной загрузке с HF помогает зеркало
export HF_ENDPOINT=https://hf-mirror.com

python scripts/refscan.py        # отбор референса: темп, слитность, нарезка по фразам
python scripts/render_v11.py     # синтез (REF=swn CUES=cues_legato.json FACTORS=1.0)
python scripts/cer_final11.py    # приёмка по CER
```

Все модели — с открытыми лицензиями, генерация полностью офлайн после первой
загрузки весов. Ключи никуда не отправляются, внешние API не используются.
