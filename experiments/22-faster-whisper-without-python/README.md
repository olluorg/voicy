# 22 — faster-whisper без Python

**Вопрос:** можно ли распознавать без Python так же точно, как faster-whisper,
раз whisper.cpp этого не смог (experiments/21).

**Код:** `rust/ct2shim/ct2shim.cpp` — C-обёртка над C++ API CTranslate2;
`rust/src/native/fwhisper.rs` — Python-часть faster-whisper 1.2.1 на Rust.

**Ответ:** да. Та же модель в той же библиотеке, вокруг неё — порт
faster-whisper функция в функцию. Результат совпадает с faster-whisper
в пределах его собственного числового шума, точность та же, короткие фразы
на 23% быстрее. По умолчанию в Rust-сервере, и Python больше не нужен совсем.

## Как устроено

faster-whisper — это две части: CTranslate2 (C++, где исполняется модель) и
Python вокруг неё — признаки log-mel, окна по 30 секунд, подсказка, проверка
на тишину, метки слов, детектор голоса для живой речи. Модель не переносится:
берётся та же `libctranslate2` 4.8.2, что лежит в колесе faster-whisper,
и её вызывают через C-обёртку (четыре вызова — `encode`, `generate`,
`detect_language`, `align`). Python переписан на Rust под теми же именами
и с теми же порогами. Заголовки CTranslate2 для обёртки — того же тега v4.8.2.

## Замеры

RTX 3080. Обе стороны — с настройками `server/engines/stt_whisper.py`:
лучевой поиск на 5 (черновик — на 2), температура 0, для файлов прошлый
текст идёт подсказкой следующему окну, для живой речи — детектор голоса.

| | faster-whisper (Python) | порт на Rust |
|---|---|---|
| Golos crowd, 298 фраз, CER | 9.92% | 9.60% |
| Golos, 300 фраз, время | 74.0 с | 57.3 с |
| термины: без контекста / подсказка / hotwords / оба | 65.7 / 68.6 / 82.9 / 85.7% | 65.7 / 68.6 / 82.9 / 85.7% |
| те же фразы, CER по четырём вариантам | 6.92 / 6.86 / 4.74 / 3.99% | 6.92 / 6.86 / 4.74 / 3.99% |
| два файла по ~2.7 мин × 7 режимов, время | 50.7 с | 48.6 с |
| память процесса за распознавание | +0.6 ГБ | +0.65 ГБ |

Сквозь HTTP-сервер Golos дал те же 300 текстов, что прямой вызов: 9.60%.

## Насколько совпадает

Повторный прогон детерминирован с обеих сторон: сам с собой каждый совпадает
100%. Друг с другом:

| набор | тексты | тексты и времена отрезков | метки слов |
|---|---|---|---|
| Golos, 300 фраз | 295 | 295 | — |
| 20 фраз с терминами × 4 варианта, 16 кГц | 80 из 80 | 80 | 80 |
| режимы на длинных файлах и фразах, 84 задания | 80 | 77 | 78 |

Расхождения — не ошибка порта, а шум самого faster-whisper. Признаки log-mel
совпадают до одного ulp: сумма `mel_filters @ magnitudes` в numpy идёт через
OpenBLAS, у которого своё ядро под каждый процессор, и порядок сложения не
повторить. Чтобы понять, сколько это весит, faster-whisper прогнан с той же
суммой во float64 — другим, но таким же верным порядком:

| | тексты | тексты и времена | метки слов |
|---|---|---|---|
| faster-whisper против себя с float64-суммой, Golos | 297 из 300 | 297 | — |
| то же, 84 задания в разных режимах | 78 | 73 | 77 |
| порт против faster-whisper, 84 задания | **80** | **77** | **78** |

Изменение последнего бита уводит faster-whisper от себя дальше, чем от него
отстоит порт. Различия — близкие развилки лучевого поиска (точка в конце,
«Смотрюшке» — «смотрюшке») и соседний шаг меток времени, 20 мс; средняя
точность от них не меняется ни в одну сторону.

## Звук не 16 кГц

Файл faster-whisper читает через PyAV: ресемплер ffmpeg (swresample)
и перевод в s16. Rust-сервер читает symphonia и ресемплирует soxr; перевод
в s16 повторён (`fwhisper::through_s16`). На 24-кГц синтезе тексты сошлись
в 74 из 80 — остальные различаются ресемплером; после приведения входа
к 16 кГц тем же PyAV — 80 из 80. Точность при этом одна и та же: термины
и CER по всем четырём вариантам совпали до сотых.

## Что пришлось учесть

- **cuBLAS 12.** CTranslate2 4.8.2 собран под CUDA 12 и открывает
  `libcublas.so.12` по имени, в момент первого вычисления; остальной сервер —
  на CUDA 13. Библиотека берётся из колеса `nvidia-cublas-cu12` и
  загружается заранее глобально — тогда CTranslate2 её находит.
- **Память.** Веса читаются в память процесса и уходят на видеокарту;
  освобождённое glibc держала у себя — +1.57 ГБ вместо +0.6 у Python.
  `malloc_trim` после загрузки вернул лишнее (`native::trim_heap`, заодно
  после загрузки синтеза): процесс с обеими моделями — 2.6 ГБ вместо 4.1.
- **Семантика Python.** `x in "строка"` — проверка подстроки, в том числе
  пустой; `round` — банковское; `np.median` — среднее двух средних. Порт
  повторяет это буквально.
- **Одна температура.** voicy передаёт одну температуру, так что запасных
  попыток нет, и степень сжатия (zlib) на результат не влияет — её порт не
  считает.

## Вывод

Распознавание без Python — с той же точностью, что у faster-whisper, и чуть
быстрее. Rust-сервер запускает все четыре движка в своём процессе:
`voicy: all engines in-process, Python is not needed`, проверки 47 из 47.
whisper.cpp остаётся по `STT_ENGINE=whisper.cpp` — как путь для железа, где
CTranslate2 нет (Intel Arc, Apple).
