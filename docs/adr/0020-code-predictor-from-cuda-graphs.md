# ADR 0020. Малая модель Qwen3-TTS — из CUDA graphs

**Дата:** 2026-09-22
**Статус:** принято

## Контекст

Синтез шёл со скоростью ×0.55 к реальному времени на любой длине текста:
136–148 мс на кадр звука при 79 мс, нужных для ×1 ([experiments/17](../../experiments/17-benchmarks/README.md)).
Для голосового агента это означало паузы между кусками потокового синтеза
до восьми секунд, а для сервера — потолок около 33 минут речи в час.

Упор был не в видеокарту: она загружена на 36%, один поток процессора — на 100%.
Каждый кадр — проход основной модели и пятнадцать проходов малой через
`generate()` из transformers. Время уходило на запуск десятков тысяч мелких
операций из Python.

## Решение

Вызовы `code_predictor.generate` перехватываются (`server/engines/tts_fast.py`):
пятнадцать шагов малой модели идут своим циклом со статическим кэшем, а проход
каждого шага записан в CUDA graph и воспроизводится одной командой.
Семплирование — как в `generate()`. Графы записываются при загрузке модели,
в режиме `thread_local`, чтобы не мешать распознавателю на той же карте.

Сработало только сочетание: свой цикл без графов дал 2%, с графами —
140 → 51–55 мс на кадр, ×1.44–1.58.

Включено по умолчанию. `TTS_FAST=0` возвращает исходный путь. На CPU не
включается: графов там нет, а цикл без них не быстрее.

## Замеры

Подробно — [experiments/18](../../experiments/18-fast-synthesis/README.md).

- Скорость: ×1.46–1.58 на текстах от 24 до 597 символов, RTX 3080.
- Качество: 30 синтезов (10 фраз × 3 сида), CER обратного распознавания 2.1%
  в обоих вариантах — одна и та же фраза, где Whisper записал число цифрами.
- Поток для агента: первый звук 3.0 с вместо 7.0 с, пауз между кусками нет —
  синтез быстрее воспроизведения.
- Память: минимум для синтеза 4.9–5.0 ГБ, в пределах точности прежнего замера.

## Отвергнуто

**Побитовое совпадение с исходником.** Статический кэш с маской и растущий кэш
выбирают разные ядра внимания; логиты расходятся на единицу-две последнего
разряда bf16, и 30% кадров идут иначе. Добиться совпадения можно только
отказавшись от статических форм, то есть от графов. Совпадение проверено
там, где оно важно, — в разборчивости.

**`torch.compile`.** Не пробовался. В режиме `reduce-overhead` он строит те же
графы, но добавляет компиляцию на каждом старте и зависит от того, как
компилятор разберёт чужой код модели. Пятнадцать графов, записанных вручную,
проще проверить и объяснить.

## Последствия

- Синтез быстрее реального времени на RTX 3080. Прежние выводы «другое железо
  не поможет» остаются верны: помогла программа.
- Звук при том же `seed` не совпадает с версией 1.2.0 побитово.
- Две трети оставшегося времени — проход основной модели. Следующий рычаг —
  тот же приём для неё; сложнее из-за трёхмерного позиционного кодирования.
