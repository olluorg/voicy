# ADR 0022. Переезд на Rust — по слоям, и на любом железе

**Дата:** 2026-09-22
**Статус:** принято; выполняется по шагам ниже

## Контекст

Сервер отвечает на вопросы, ради которых делался, и дальше важны три вещи:
скорость, память и простая доставка. Сейчас доставка — это Python 3.12, torch
и несколько гигабайт зависимостей, а образ собирается только под x86-64 с CUDA.

Требования к железу:

- **не только NVIDIA:** видеокарты Intel Arc и работа на одном процессоре —
  такие же цели, как CUDA;
- **не только x86:** процессоры ARM64 поддерживаются наравне.

Сейчас код знает только CUDA и процессор: устройство определяется через torch
(`engines/device.py`), ARM не проверялся, Intel Arc не поддержан.

Слои и швы между ними — на схеме в README (`docs/architecture.svg`):
HTTP API, контракт движков (ADR 0021), среда исполнения, устройство. Любой
слой меняется, не трогая соседей, — это и делает переезд постепенным.

## Решение

**Переезжать по слоям, и после каждого шага версия рабочая.** Rust вытесняет
Python участок за участком, начиная с тех, где риск меньше.

1. **Проверки API и учебный движок.** Набор проверок ходит к серверу только
   по HTTP и WebSocket, поэтому одинаково проверяет любую его реализацию.
   Учебный движок вместо речи отдаёт тон, вместо распознавания — известный
   текст: проверки идут за секунды, без видеокарты, в CI на amd64 и arm64.
   Запуск — одной командой, результат — один файл отчёта с описанием железа:
   прогоны на чужих машинах делают люди, а не CI.
2. **Слой устройств в контракте.** Движок объявляет, какие устройства умеет;
   выбор — `VOICY_DEVICE=auto|cuda|intel|cpu`, без torch. Первый замер на
   Intel Arc — Qwen3-TTS на PyTorch XPU, ещё до Rust.
3. **CLI на Rust.** Он говорит с сервером только по HTTP; клиенты и код-агенты
   получают один бинарник под каждую платформу.
4. **Движки в отдельном процессе.** Python-движки отвечают серверу по протоколу,
   повторяющему контракт; нынешний сервер зовёт их через него. Язык ещё не
   меняется — меняется граница, и её ошибки ловятся на знакомом коде.
5. **Сервер на Rust** поверх того же процесса движков. Какое-то время обе
   реализации проходят один набор проверок; Python-сервер остаётся запасным
   на один выпуск.
6. **Родные движки по одному:** детектор голоса, конец реплики, распознавание,
   синтез. Каждый выбирается переменной, Python-вариант живёт рядом, пока родной
   не прошёл замеры на каждом целевом железе.
7. **Образы под все платформы** и сервер без Python. Процесс Python-движков
   остаётся необязательным: через него новая модель, у которой есть только
   код на PyTorch, подключается в тот же день.

**Среды исполнения выбираются по покрытию железа.** Основа — GGML (llama.cpp,
whisper.cpp) и ONNX Runtime: обе работают на CUDA, на Intel (SYCL и Vulkan
у GGML, OpenVINO у ONNX Runtime) и на процессорах x86 и ARM, и у обеих есть
привязки к Rust. Из этого следует:

- candle — не основа: видеокарт Intel он не поддерживает;
- распознавание — кандидат whisper.cpp: CTranslate2, на котором стоит
  faster-whisper, Intel Arc не поддерживает;
- ускорения под одно железо — CUDA graphs сейчас, свои ядра на CUDA Rust
  когда-нибудь — остаются необязательной надстройкой внутри движка. Базовый
  путь обязан работать везде.

**Порог для каждого шага:** набор проверок зелёный, а у движка CER по
`scripts/engine_eval.py` не хуже нынешнего, скорость или память лучше —
на каждом железе, где он заявлен. Не прошёл — остаётся прежний вариант.

## Где проверяется железо

| Железо | Где |
|---|---|
| NVIDIA, x86-64 | машина автора: RTX 3080 |
| процессор x86-64 | там же и в CI |
| процессор ARM64 | CI: arm64-раннеры GitHub; модели — на живом устройстве |
| Intel Arc | машина брата автора: прогон по команде, отчёт файлом |

## Отвергнуто

**Переписать сразу всё.** Без набора проверок правильность нового сервера
держалась бы на ручных прогонах, а сломанное было бы видно только клиентам.

**Встроить Python в Rust-сервер (PyO3).** Доставка осталась бы прежней —
тот же Python с torch внутри, — а блокировка интерпретатора легла бы на сервер.

**Выбрать среду исполнения по удобству, а не по железу.** candle удобнее всего
из Rust, но закрыл бы Intel Arc.
