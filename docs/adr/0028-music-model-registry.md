# ADR 0028. Музыка: несколько моделей сразу, модель выбирает запрос

**Дата:** 2026-10-03
**Статус:** принято 2026-10-03; родными движками встали ACE-Step (acestep.cpp), Stable Audio 3 (sa3.cpp) и HeartMuLa (свой порт, 2026-10-04); замер — [experiments/29](../../experiments/29-music-models/README.md)

## Контекст

После речи, распознавания и звуков (ADR 0027, отклонён) — музыка: фон под
озвучку, инструментал по описанию, песня по тексту на русском и английском.

Открытых моделей музыки много, и они сильны в разном: одна быстрая и держит
длину, другая лучше поёт текст, третья только инструментал, у четвёртой
некоммерческая лицензия. Выбрать за пользователя одну «лучшую» — значит
отнять у него остальные. Решение пользователя (2026-10-03): **модель
сменяема, и выбирает её тот, кто просит музыку**, под свою задачу.

До сих пор движок каждого вида выбирался один на сервер переменной окружения
(`TTS_ENGINE`, ADR 0021). Для музыки этого мало.

## Решение

**Вид движка `music` — реестр, а не один движок.** Сервер предлагает все
установленные модели сразу, запрос называет нужную полем `model`; без него
берётся `MUSIC_MODEL` или первая установленная. Модели ставятся отдельно
от речи (`voicy setup music`, `music-xl`): кому нужна речь, не качает
гигабайты музыки, а кому нужна одна модель, не платит за остальные.

**Каждая модель объявляет карточку,** и `/v1/music/models` (`voicy
music-models`) её показывает:

- `sample_rate`, `channels`;
- `max_seconds` и `length`: `exact` — модель делает ровно столько, сколько
  просили, или `ceiling` — просьба лишь потолок, конец песни модель решает
  сама;
- `vocals` (умеет петь текст), `instrumental` (умеет без голоса),
  `languages` — на каких языках поёт;
- `license` и `commercial` — пригодны ли веса для коммерческого
  использования.

Чего модель не умеет, получает 400 до очереди (ADR 0021): текст песни
у модели без вокала, язык не из `languages`, длина вне пределов.

**Форма запроса — как у ElevenLabs** (`POST /v1/music`: `prompt`,
`music_length_ms`, `force_instrumental`, `model_id`, `?output_format=`), как
звуки повторяли их `/v1/sound-generation`: клиенту достаточно сменить адрес.
Их имена моделей (`music_v1`) означают модель по умолчанию — клиенты шлют
их сами. Сверх формы — `lyrics`, `language`, `duration_seconds`, `seed`.
`composition_plan` в контракт пока не вошёл и получает 400, а не тихо
пропускается. Задание — `/v1/jobs/music`; в результате, кроме звука, —
что выбрала модель: темп, тональность, текст, если писала его сама.

**Запрос говорит на языке API, а не модели.** Описание — одна фраза
(`prompt`), текст песни (`lyrics`) с разметкой частей `[verse]`, `[chorus]`.
Без текста модель с LM пишет его сама, как у ElevenLabs; инструментал —
явно (`force_instrumental`). Язык — ISO 639-1, длина — секунды, `seed`.
Подгонка под модель — забота движка: HeartMuLa берёт короткие теги, а не
фразу, и выключателя инструментала у неё нет; ACE-Step сам дописывает план
песни своей LM.

**По умолчанию — только коммерчески пригодные веса.** Модель с
некоммерческой лицензией ставится лишь явно, а карточка и ответ (`X-Model-License`)
говорят о лицензии.

**Видеопамять — одна модель музыки за раз, и по частям.** На стенде
PyTorch HeartMuLa заняла 9.95 ГБ из 10, ACE-Step — 7.6 ГБ: целиком рядом
с синтезом речи ни одна не встаёт. Поэтому в памяти одна модель музыки:
запрос к другой сначала освобождает прежнюю. А ACE-Step через acestep.cpp
держит в видеопамяти одну свою часть за раз — LM, потом DiT, потом VAE —
и встаёт рядом с речью. Все части сразу — `MUSIC_KEEP_LOADED=1`, для
большой карты.

**Звук — стерео 48 кГц.** Кодировщики voicy умели только моно: речь.
Для музыки они получили каналы (opus 128 кбит/с, mp3 192), а речь кодируется
как раньше, байт в байт.

**Движки родные, без Python** (ADR 0022, ADR 0026). PyTorch — только стенд
замера в `scripts/music_*.py`; в сервер модель попадает в родном виде:

- **ACE-Step — через [acestep.cpp](https://github.com/ServeurpersoCom/acestep.cpp)**
  (MIT, C++17 на GGML: CUDA, Vulkan, Metal, CPU; LM, кодировщик текста, DiT,
  VAE, кванты GGUF). Он собирается статической библиотекой `acestep-core`
  с C++-интерфейсом; поверх — тонкая обёртка `extern "C"`, которую
  `voicy-core` грузит при запуске, как llama.cpp (`native/llama.rs`).
  Приёмка — по ADR 0022: на 3080 не медленнее PyTorch (17–22 с на 60–75 с
  музыки) и не хуже по оценщику на том же наборе.
- **HeartMuLa порта не имеет.** Устроена как Qwen3-TTS, который voicy уже
  исполняет сам (experiments/20): бэкбон Llama-3.2 3B ведёт цикл кадров,
  малый декодер достраивает кодбуки, кодек делает звук. Порт — та же работа:
  бэкбон в llama.cpp, декодер и кодек — в GGML или ONNX. Браться за него
  стоит, только если прослушивание покажет, что она чем-то нужна сверх ACE-Step.

## Что показали две модели

Контракт проверяется двумя непохожими моделями, как ADR 0021 проверял синтез
вторым движком:

| | ACE-Step 1.5 | HeartMuLa-oss-3B |
|---|---|---|
| устройство | LM 0.6B планирует, DiT (turbo, 8 шагов) рисует | языковая модель над кодеком 12.5 Гц |
| длина | ровно по просьбе | сама решает: 55 с при потолке 98 |
| описание | фраза | теги |
| инструментал | флаг, голоса нет ни в одном из 15 дублей | нет: голос в каждом из 10 дублей |
| прогресс | доля шагов, длина известна заранее | секунды готового звука |
| 75 с песни на 3080 | 23 с, 7.6 ГБ | 213 с на 55 с, 9.95 ГБ |

`length` и прогресс в двух формах (ADR 0021) пришли именно отсюда: из одной
модели их не вывести.

## Родной ACE-Step: что показала сборка

RTX 3080, сервер с прогретыми синтезом и распознаванием, `ace-step` (DiT 2B
turbo Q8, LM 0.6B Q8), веса на ext4:

| | стенд PyTorch | acestep.cpp в сервере |
|---|---|---|
| 75 с песни | 19–22 с | 7.6–8.4 с, из них счёт ~5 с |
| пик видеопамяти | 7.6 ГБ, одна модель | 2.5–4.6 ГБ сверх речи |

- **Узкое место — VAE**, а не модели: кусок в 1024 латентных кадра занял
  8.4 ГБ, рядом с речью памяти не хватило, и ggml прервал весь процесс.
  Кусок теперь выбирается перед каждым декодированием по свободной памяти
  (1024/512/256/128, ~7.5 МБ на кадр); 512 декодирует даже быстрее 1024.
- **Все части в памяти сразу (`MUSIC_KEEP_LOADED`) на 10 ГБ медленнее**:
  они уходят в общую память Windows, DiT считается 13.8 с вместо 0.75.
  Поэтому по умолчанию — одна часть за раз.
- **Загрузка частей решает всё на медленном диске**: с диска Windows через
  WSL — 26 с на песню вместо 8, DiT XL грузится 47 с.
- **Длина**: LM пишет коды с частотой 5 Гц и заканчивает на несколько кодов
  раньше (74.2 с вместо 75), так что сервер доводит длину до заказанной
  тишиной в конце или обрезкой с затуханием.
- **Громкость**: громкий мастер после opus перескакивал пик (0.95 → 1.21),
  поэтому перед кодеками с потерями дорожка приглушается до −1 дБFS, если
  громче.
- ggml-форк acestep.cpp в одной библиотеке со скрытыми символами уживается
  в процессе с ggml от llama.cpp: наружу видно пять функций `vac_*`.

## Три модели — три карточки

| | ACE-Step | Stable Audio 3 Medium | HeartMuLa |
|---|---|---|---|
| движок | acestep.cpp, своя обёртка | sa3.cpp, его C ABI под обёрткой | свой порт: llama.cpp + ONNX Runtime |
| поёт / инструментал | да / да | нет / да | да / нет |
| текст | пишет сам, если не дан | — | только заданный, без него — 400 |
| длина | ровно заказанная | ровно заказанная, сама не выбирает | заказ — потолок, конец решает модель |
| описание | фраза | фраза по-английски | теги по-английски |

Контракт выдержал три непохожие модели без изменений, кроме двух полей
карточки: `needs_lyrics` и `chooses_length`.

**Память по фазам — правило для всех трёх.** Без `MUSIC_KEEP_LOADED` модель
держит в видеопамяти только работающую часть: ACE-Step — LM, DiT, VAE по очереди
(acestep.cpp сам), SA3 — режим FRUGAL своего ABI, HeartMuLa — языковую часть,
потом DiT кодека, потом его декодер. Декодеры звука делят работу на куски по
свободной памяти: VAE ACE-Step — по 1024/512/256 кадров, декодер HeartCodec —
по 186.

**Осталось:**

- сборка `voicy-acestep` и `voicy-sa3` в выпусках для каждой платформы и
  бэкенда (CUDA, Vulkan, Metal, CPU) — пока они собираются вручную;
- готовые файлы HeartMuLa для `voicy setup` (как у Qwen3-TTS — переведённые
  веса в репозитории на Hugging Face); пока их делают скрипты перевода;
- синтезу и распознаванию — отдавать видеопамять на время тяжёлой музыки:
  HeartMuLa рядом с ними на 10 ГБ упирается в 10.04 ГБ из 10.24.

## Отвергнуто

**Выбрать одну модель замером**, как для звуков (ADR 0027). Замер
по-прежнему нужен, но для карточек и умолчания, а не для отсева.

**Сначала движок на Python в дочернем процессе, потом родной** — так
предлагал ADR 0027 для звуков. Сервер полностью на Rust (ADR 0026), Python
в нём — запасной путь для моделей без родной формы, а не ступень для новых.
У ACE-Step родная форма уже есть.

**Выбор модели окружением сервера**, как у синтеза. Тогда сменить модель
может только тот, кто запускает сервер, а не тот, кто просит музыку.
