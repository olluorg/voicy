# ADR 0016. Словарь произношений собирается автоматически

**Дата:** 2026-07-27
**Статус:** принято (отменяет ручную проверку из [ADR 0015](0015-stress-control-in-qwen3-tts.md))

## Контекст

Требование заказчика: никакой ручной работы, на выходе должен быть
автоматизированный инструмент без участия человека.

Это отменяет схему из [ADR 0015](0015-stress-control-in-qwen3-tts.md), где словарь
проверялся на слух. Значит нужна автоматическая проверка произношения — включая
ударение, где две предыдущие попытки провалились.

## Почему предыдущие детекторы не работали

Оба искали ударный слог **внутри** сигнала, по энергии:

| Попытка | Метод | Результат |
|---|---|---|
| первая | деление на равные по энергии доли | 70% «ошибок» на живой человеческой речи |
| вторая | пики полосовой огибающей, вес = высота × ширина | **16%** верных при 25% у случайного угадывания |

Вторая попытка хуже случайной, то есть систематически ошибается. Прежде чем
винить детектор, проверил эталон: Silero действительно уважает метки `+` —
при переносе метки звук меняется. Разметка была верной, провалился метод.

Причина в том, что энергия в русском слове отражает открытость гласной
и взрывность согласного не меньше, чем ударение.

## Метод, который сработал: сопоставление с эталоном

Задача перевёрнута. Ничего не сегментируем — спрашиваем, **на какую из известных
записей похожа неизвестная**.

Silero принимает явную позицию ударения, поэтому слово синтезируется с ударением
на каждом слоге по очереди. Это эталоны. Кандидат оценивается только по форме
контура громкости: полосовая огибающая, обрезка тишины, растяжение к общей длине,
z-нормировка. Тембр и темп при этом сокращаются, остаётся ритм выделенности.

**Валидация межголосовая по построению**: эталоны берутся у одного голоса Silero,
проверочные записи — у другого. Это та же рассогласованность, что будет между
эталонами Silero и выходом Qwen.

| | Результат |
|---|---|
| точность восстановления позиции ударения | **77%** (48 из 62) |
| случайное угадывание | 25% |

77% недостаточно для одиночного решения, поэтому кандидат синтезируется
несколькими сидами и позиция определяется голосованием.

## Конвейер

Каждая запись словаря решается двумя независимыми автоматическими проверками:

1. **Разборчивость.** Термин синтезируется в несущей фразе и распознаётся
   обратно; написание, дающее другое слово (случай «Валдгад» вместо wildcard),
   отсеивается по расстоянию строк. Порог сходства 0.62.
2. **Ударение.** Контур сопоставляется с эталонами Silero, позиция сравнивается
   с ожиданием RUAccent.

Термин, не прошедший проверку, прогоняется через порождённые правилами
перезаписи — удвоение ударной гласной, разбиение на два слова, дефис — и первый
кандидат, прошедший обе проверки, попадает в словарь.

Каждая запись хранит, какая проверка сработала и с каким результатом.

## Ограничение, которое остаётся

Конвейер добивается **того ударения, которое считает верным RUAccent**. Там, где
сам акцентуатор ошибается на жаргоне — а на «дженерики» он даёт второй слог,
тогда как в речи разработчиков слышен первый, — инструмент этого знать не может
и закрепит ошибку акцентуатора.

Это не устраняется автоматикой в принципе: вопрос о правильном ударении
в заимствованном термине — вопрос о норме, а не об измерении. Единственный
автоматический выход — заменить источник ожиданий на словарь жаргона, если такой
найдётся.

## Последствия

- Пополнение словаря новыми терминами не требует человека: скрипт прогоняется
  заново и дописывает записи.
- Стоимость: около 12 секунд генерации на термин, то есть весь словарь — минуты.
- Детекторы, не прошедшие валидацию, остаются в репозитории как отрицательные
  результаты, чтобы их не изобрели заново.
