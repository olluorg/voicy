# ADR 0019. Синтез потоком по предложениям, ключ доступа, ошибки как у OpenAI

**Дата:** 2026-09-21
**Статус:** принято

## Контекст

После [ADR 0018](0018-voice-agent-turns-and-context.md) агент слышит потоком,
а говорит только целым файлом. Замер на RTX 3080: синтез медленнее реального
времени — 5.1 с звука за 9.5 с, ответ из трёх предложений (13.6 с) за 26–30 с.
Всё это время агент молчит.

Ещё два пробела мешают поставить сервер рядом с чужим кодом. Сервер открыт
всем, кто видит порт, а в docker он слушает `0.0.0.0`. И ошибки приходят
как `{"detail": ...}`: официальные клиенты OpenAI ждут `{"error": {...}}`
и показывают вызывающему только строку статуса.

## Решение

**Синтез кусками, по предложениям.** Qwen3-TTS отдаёт звук только готовой
фразой, поэтому поток собран снаружи: текст режется, каждый кусок синтезируется
отдельно и уходит, как только готов. Два входа: `stream_format` у
`/v1/audio/speech`, параметр OpenAI, и WebSocket `/v1/audio/speech/stream`,
куда агент шлёт текст по токенам и `cancel`, когда его перебили.

Где резать, решает скорость. Синтез медленнее воспроизведения, так что паузы
между кусками будут. На границе предложений они звучат как вдох, посреди фразы —
как заикание. Поэтому куски идут по предложениям, и только первый режется
раньше, по запятой, — его слушатель ждёт дольше всего. Короткое предложение
склеивается со следующим, если оно уже известно: у вызова есть постоянная цена,
«Да.» синтезируется 1.45 с ради 0.64 с звука.

Отмена проверяется на каждом шаге декодирования — тем же счётчиком шагов,
что и прогресс.

**Ключ доступа — по желанию, в форме OpenAI.** `VOICY_API_KEY` включает
проверку `Authorization: Bearer` на всех `/v1/`, WebSocket тоже. Для браузера,
который не ставит заголовки на `EventSource` и WebSocket, принимается
`?api_key=`. `/health` и консоль открыты: первое нужно docker и CLI, второе
само спрашивает ключ. Проверка — чистым ASGI-посредником: HTTP-посредник
FastAPI WebSocket не видит.

**Ошибки — в формате OpenAI.** Все ответы с ошибкой — `{"error": {"message",
"type", "param", "code"}}`. Ошибка параметров — 400, как у OpenAI, а не 422.
Файл, который не декодируется как звук, — 400, а не 500: виноват вход.

## Замеры

Ответ из трёх предложений, 13.6 с звука, RTX 3080:

| Как | Первый звук | Весь ответ |
|---|---|---|
| целиком | 29.8 с | 29.8 с |
| `stream_format=audio` | 7.0 с | 25.8 с |
| WebSocket, текст токенами по 50 мс | 7.0 с | 24.9 с |

Отмена по WebSocket: 0.1 с от `cancel` до `cancelled`, оборванный кусок
не отправлен. Официальный клиент OpenAI опознаёт ошибки как
`AuthenticationError` и `BadRequestError` и читает поток через
`with_streaming_response`.

## Отвергнуто

**Поток внутри предложения.** Можно было бы декодировать аудио-токены по мере
генерации. Но при синтезе медленнее реального времени это дало бы паузы посреди
слов, а первый звук ускорило бы лишь на часть предложения. Имеет смысл вернуться,
если синтез станет быстрее реального времени.

**Синтез потоком через очередь заданий.** Ответ агента за длинным файлом —
не ответ. Поток берёт блокировку синтезатора по куску, и идущее задание
задерживает его только до своего конца.

**Оставить `detail` рядом с `error` ради совместимости.** Второй формат
навсегда ради пары часов после релиза 1.1.0. CLI и консоль переведены
на новый формат в том же изменении.

## Последствия

- Внешние клиенты, читавшие `detail`, должны читать `error.message`.
- Ошибка параметров теперь 400 вместо 422.
- С `stream_format` синтез идёт мимо очереди и `X-Job-Id` не возвращает.
- Звук потока — отдельные синтезы: интонация не переходит через границу куска,
  а при заданном `seed` каждый кусок звучит так же, как синтезированный отдельно.
