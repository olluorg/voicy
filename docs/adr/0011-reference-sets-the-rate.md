# ADR 0011. Темп задаётся референсом, а не постобработкой

**Дата:** 2026-07-26
**Статус:** принято (отменяет растяжение как основной механизм из [ADR 0005](0005-speaking-rate-via-pauses-and-time-stretch.md))

## Контекст

Вопрос заказчика: «Ты искусственно замедлил звук?»

Да. Рекомендованный вариант использовал `atempo=0.66` — растяжение готового аудио
в полтора раза. Это выходило далеко за границу осторожности, которую [ADR 0005](0005-speaking-rate-via-pauses-and-time-stretch.md)
сам же и обозначил («сильнее 0.8 — осторожно, артефакты слышны, хотя CER их
не показывает»).

Вопрос вскрыл две ошибки подряд.

## Ошибка 1: референс выбирался только по разборчивости

F5 — zero-shot модель: она копирует из референса не только тембр, но и **темп
речи**. Шесть нарезанных клипов различались по темпу вдвое:

| Референс | слов/мин |
|---|---|
| Тургенев, «Дворянское гнездо» | 93 |
| Пушкин | 99 |
| Достоевский, «Записки из подполья» | 103 |
| **Лесков — выбранный** | **121** |
| Достоевский, «Белые ночи» | 138 |
| Тургенев, «Поездка в Полесье» | 144 |

Референс отбирался по CER ([ADR 0006](0006-espeech-rlv2-with-human-reference.md)),
и его темп ни разу не измерялся. В результате был взят один из самых быстрых
чтецов, а следствие лечилось растяжением.

## Ошибка 2: клипы резались по таймеру, а не по фразам

Первые референсы вырезались фиксированным окном 13 секунд с отметки 45 с. Окно
попадало в середину фразы, и Whisper выдавал обрубок вроде «улиц губернского
города о дело происходило в 1842 году».

F5 получает транскрипт референса дословно. Кривой транскрипт портит **каждый**
синтезируемый сегмент, а не только начало.

## Решение

1. **Референс отбирается по темпу и по разборчивости вместе**, а не по одной
   разборчивости.
2. **Клип режется по границам предложений** — используются границы сегментов
   Whisper, так что клип и его транскрипт согласованы точно.
3. **Растяжение перестаёт быть основным механизмом.** Нужный темп берётся
   из референса; постобработка остаётся доводкой на несколько процентов, если
   вообще нужна.

## Результат

Тот же чтец (Тургенев), перерезанный по фразам:

| | Было | Стало |
|---|---|---|
| темп | 121 слов/мин у референса | **74 слов/мин у референса** |
| растяжение | ×0.66 | **×1.00, не применяется** |
| темп результата | 97 слов/мин | **91 слов/мин** |
| пауз | 35 | **142, все модельные** |
| CER | 3.2% | **1.0%** |

**CER 1.0% — лучший результат за всё исследование.**

Тот же клип с обрубленным транскриптом давал 7.3%. Одна только чистая нарезка
дала семикратное улучшение.

## Последствия

- Из конвейера уходит и растяжение тоже. Остаётся: текст → реплики → синтез →
  склейка встык. Ни одного параметра, подкрученного «на слух».
- Требование к референсу становится составным: чистая запись, медленный чтец,
  нарезка по границам фраз, точный транскрипт. Все четыре свойства проверяемы
  автоматически.
- Доля тишины выросла до 32.7% — но это тишина самого чтеца, с медианой 472 мс,
  а не вставленные двухсекундные провалы, которые отвергнуты в [ADR 0010](0010-no-inserted-silence.md).
  Совпадение чисел обманчиво: важно не сколько тишины, а откуда она.

## Мораль

Четыре итерации подряд компенсировали следствие вместо причины: паузы правились
затуханиями, темп — растяжением. Оба параметра принадлежали референсу, и оба
чинились в постобработке.

Признак, который стоило заметить раньше: если параметр приходится подкручивать
всё сильнее и сильнее, скорее всего его источник находится выше по конвейеру.
