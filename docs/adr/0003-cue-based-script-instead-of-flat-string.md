# ADR 0003. Скрипт — список типизированных реплик, а не плоская строка

**Дата:** 2026-07-26
**Статус:** принято

## Контекст

Даже с правильно написанным текстом озвучка шла монотонно: одна скорость от
начала до конца, без замедления на терминах и без пауз перед тем, что нужно
запомнить. Живой преподаватель делает ровно обратное — притормаживает на новом
понятии и держит паузу после главной мысли.

Плоская строка такого выразить не может: у неё один темп на весь текст.

## Решение

Единица аудио-скрипта — **реплика с типом**. Тип задаёт темп и паузы вокруг:

| Тип | Скорость | Пауза до / после |
|---|---|---|
| `narration` — связки, повествование | ×1.02 | 120 / 120 мс |
| `term` — новое понятие, новый случай | ×0.88 | 420 / 260 мс |
| `key` — фраза, которую надо запомнить | ×0.86 | 480 / 420 мс |
| `question` — сам вопрос | ×0.92 | 300 / 250 мс |
| `beat` — явная пауза на подумать | — | задаётся числом |

Таблица живёт **в коде одним объектом**: правка в одном месте меняет дикцию
всего курса.

Паузы вставляются реальными сэмплами при склейке, а не выпрашиваются у модели —
длительность получается ровно заданная.

## Обоснование

- Ритм становится свойством контента, а не побочным эффектом модели.
- Функция «реплики → план синтеза» чистая и тестируется тривиально.
- Разборчивость от этого не страдает, а **растёт**: 6.2% против 7.3% CER
  у того же текста, синтезированного одним куском. Замедление на терминах
  помогает не только человеку, но и распознавалке.

## Последствия

- Покусочный синтез медленнее цельного: ×3.2 против ×4.3 к реальному времени.
  Корпус — 4.5 часа генерации вместо 3.5. Приемлемо для разовой операции.
- Каждая реплика синтезируется независимо от общего референса, поэтому стыки
  требуют обработки — см. [ADR 0004](0004-pause-shape-fade-and-room-tone.md).
- В контенте появляется структура: аудио-скрипт хранится как список реплик.
