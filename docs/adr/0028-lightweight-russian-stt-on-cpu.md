# ADR 0028. Лёгкое распознавание русской речи на слабом CPU (1 vCPU, 2 ГБ RAM)

**Дата:** 2026-11-27
**Статус:** предложено

## Контекст

По умолчанию `voicy` распознаёт речь моделью `faster-whisper-large-v3-turbo`
через CTranslate2 (`rust/core/src/stt.rs`). На сервере с видеокартой это
даёт высокое качество, но на дешёвом VPS без GPU (**1 vCPU, 2 ГБ RAM**)
текущая конфигурация неработоспособна:

1. На одном потоке CPU `large-v3-turbo` (INT8) занимает **1878.4 МБ RAM**
   на пике — почти всю память VPS, что приводит к OOM при работе ОС
   и веб-сервера.
2. Скорость инференса на одном потоке составляет **RTF 1.540** (в полтора
   раза медленнее реального времени).
3. Полный набор моделей (`voicy setup`) занимает около 8 ГБ на диске
   вместе с `Qwen3-TTS`, а проверка `all_native` в `rust/src/engines.rs`
   при отсутствии TTS пытается запустить дочерний процесс Python.

Требуется решение для автономного сверхлёгкого STT-сервера на базе
`voicy` (один бинарник на Rust без Python): только распознавание русской
речи на CPU, уверенная работа в пределах 2 ГБ RAM и 1 vCPU, коммерчески
дружелюбная (пермиссивная) лицензия.

## Замер моделей (CPU-only, 1 поток)

Испытания проведены в изолированных процессах (`OMP_NUM_THREADS=1`,
`intra_op_num_threads=1`, `cpu_threads=1`, `CUDA_VISIBLE_DEVICES=""`) на
7 эталонных русских записях из `server/voices/` (общая длительность
**76.02 с**, эталоны в `server/voices/voices.json`):

Также рассмотрены новые модели 2025–2026 годов:
- `Qwen3-ASR-0.6B` (~523 МБ – 1 ГБ в 4/5-bit, требует ~4 ГБ RAM) и
  `NVIDIA Parakeet TDT 0.6B v3` (INT8 ~670 МБ на диске, пик ~2 ГБ RAM)
  не укладываются с запасом в 2 ГБ VPS.
- `SenseVoiceSmall` (~1.1–1.5 ГБ RAM на CPU) оставляет слишком мало
  памяти для ОС.
- `Moonshine` (27M) оптимизирован под edge, но моноязычные tiny-модели
  выпущены без русского языка.

## Решение

1. **Добавить в `voicy-core` нативный бэкенд `GigaAM-v3` (ONNX INT8)**
   на базе уже подключённого крейта `ort` (`rust/core/Cargo.toml`) и
   имеющегося препроцессинга (`realfft` / `soxr-sys`, `rust/core/src/native/mel.rs`):
   - Варианты `gigaam-v3-e2e-ctc` (с пунктуацией и регистром) и
     `gigaam-v3-ctc` (максимальная точность слов), выбор через `STT_ENGINE=gigaam`.
   - Потоки ONNX Runtime ограничиваются под слабый CPU (`intra_op_num_threads = 1`
     или по числу ядер).
   - Лицензия модели (`ai-sage/GigaAM-v3` / `salute-developers/GigaAM`) — **MIT**,
     полностью совпадает с лицензией `voicy`.

2. **Сегментация длинного аудио через `Silero VAD`:**
   - Использовать уже встроенный `silero_vad_v6.onnx` (`rust/core/src/native/listen.rs`)
     для нарезки длинных записей на фразы до инференса GigaAM.
   - Это удерживает пиковое потребление RAM в пределах **~350–500 МБ**
     независимо от длины аудиофайла и даёт готовые таймкоды сегментов для `srt`/`vtt`.

3. **Режим сервера «только STT»:**
   - Разрешить явное отключение синтеза и детектора конца реплики
     (`TTS_ENGINE=none`, `TURN_ENGINE=none` или `VOICY_MODE=stt`) в
     `rust/src/engines.rs`, чтобы сервер не требовал `Qwen3-TTS` и не
     пытался запускать Python-хост (`Host::spawn`).

4. **Облегчённый профиль установки (`voicy setup --stt-lite`):**
   - Скачивать только CPU-библиотеку `onnxruntime` (~15–20 МБ),
     `silero_vad_v6.onnx` (~2 МБ) и `gigaam-v3-*.int8.onnx` со словарём
     (~225 МБ) — суммарно **~250 МБ на диске** вместо ~8 ГБ.

## Последствия

- Весь стек (`voicy` + `ort` + `Silero VAD` + `GigaAM-v3`) остаётся под
  единой пермиссивной лицензией **MIT** и работает в одном нативном
  бинарнике на Rust без Python.
- Потребление памяти падает в **5.4 раза** (с ~1.88 ГБ до ~350 МБ),
  скорость распознавания на 1 потоке CPU вырастает примерно в **7 раз**
  (RTF с 1.54 до 0.21–0.23), при сохранении близкого качества
  (CER 0.8–1.1% против 0.8%).
- В режиме «только STT» маршруты синтеза речи (`/v1/audio/speech` и др.)
  должны возвращать `501` / `503`.

## Отвергнуто

- **`faster-whisper` (`tiny`, `base`, `small`) для русского STT на CPU:**
  `tiny` и `base` дают неприемлемый WER (37.2% и 30.3%), а `small`
  требует ~712 МБ RAM и работает на грани реального времени (RTF 0.939),
  проигрывая `GigaAM-v3` и по скорости, и по точности.
- **`Vosk` (`vosk-model-small-ru`):** рекордная скорость (RTF 0.022), но
  существенно хуже качество (WER 13.8%, без пунктуации); при этом
  `GigaAM-v3` уже даёт четырёхкратный запас к реальному времени на 1 потоке.
- **`T-one` (`t-tech/t-one`):** на общих русских записях уступает
  `GigaAM-v3` по точности (WER 9.7%) и требует больше памяти (~509 МБ),
  ориентирован прежде всего на потоковую телефонию 8 кГц.
