# Как выпускаются и заверяются файлы voicy

Этот документ — обещание, по которому можно проверить любой выпущенный файл:
откуда он взялся, кто мог его выпустить и что именно заверено. Он же требуется
[SignPath Foundation](https://signpath.org/terms.html) от проектов, которые
просят бесплатную подпись, — заявка подана не будет без него.

## Что и чем заверено сейчас

У проекта **нет сертификата удостоверяющего центра**: подпись для Windows
стоит от 150 $ в год, а сервис Microsoft частным лицам вне США и Канады
не продаётся ([документация Microsoft](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)).
Поэтому Windows покажет предупреждение SmartScreen, а вместо подписи файлы
заверены двумя способами, которые ничего не стоят и проверяются кем угодно:

- **контрольная сумма** — `*.sha256` рядом с каждым файлом выпуска;
- **подтверждение сборки** (build provenance) — GitHub подписывает утверждение
  «этот файл собран таким-то workflow из такого-то коммита», а `gh` его
  проверяет:

```bash
gh attestation verify voicy-windows-x64.exe --repo olluorg/voicy
sha256sum -c voicy-linux-x64.sha256
```

Если проверка не сходится — файл не наш, и запускать его не нужно.

## Откуда берутся файлы

- Собирает только GitHub Actions — [`.github/workflows/release.yml`](../.github/workflows/release.yml),
  по тегу `v*`, из исходников этого репозитория. Собранное руками к выпускам
  не прикладывается: иначе заверять было бы нечего.
- Сборка ничего не скачивает, кроме зависимостей Rust с crates.io: заголовки
  CTranslate2 и исходники обёртки лежат в репозитории. Модели и библиотеки
  движков качает уже сам бинарник (`voicy setup`) — в выпуск они не входят.
- Версия в имени выпуска совпадает с `version` в `rust/Cargo.toml` и с тем,
  что печатает `voicy --version`.

## Кто может выпустить

- Право ставить теги и менять workflow есть у владельца репозитория; сейчас
  это один человек — [@olluorg](https://github.com/olluorg).
- Вход в GitHub — с двухфакторной аутентификацией.
- Каждый выпуск подтверждается вручную: тег ставит человек, автоматических
  выпусков по расписанию нет.
- Если появится подпись от удостоверяющего центра, правило останется тем же:
  подписывается только то, что собрано в CI из публичного коммита, и каждый
  выпуск подтверждается вручную.

## Что внутри бинарника

Свой код — MIT. Из чужого в файл попадают: обёртка над CTranslate2 (её
исходник и заголовки CTranslate2 4.8.2 — MIT), libopus (BSD-3-Clause),
LAME (LGPL-2.1), libsoxr (LGPL-2.1) и библиотеки Rust с их лицензиями.
Закрытых компонентов нет. Модели скачиваются отдельно и в файл не входят;
их лицензии перечислены в [README](../README.md).

## Если что-то не так

О подозрительном файле, расхождении контрольной суммы или неудачной проверке
подтверждения — issue в репозитории. О предполагаемой уязвимости — тоже issue,
пока у проекта нет отдельного канала; придумывать вид приватной связи, которого
нет, здесь не будем.
