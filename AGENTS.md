# voicy для агента

Локальный синтез и распознавание речи. Ключей нет, сеть не нужна,
всё исполняется на этой машине.

**Озвучить текст — одна команда:**

```bash
./voicy say "Текст, который нужно озвучить" out.opus
```

В stdout уходит путь к файлу, в stderr — сколько получилось звука и за сколько.
Сервер не поднят — `./voicy up` (см. ниже).

## Что нужно чаще всего

```bash
./voicy say "текст" out.opus                # синтез
./voicy say @статья.md out.opus             # текст из файла
cat статья.md | ./voicy say - out.opus      # или из потока
./voicy say "текст" out.opus --voice dostoevsky --speed 0.9

./voicy hear запись.opus                    # распознавание → текст в stdout
./voicy hear запись.opus --format srt       # субтитры
./voicy hear созвон.opus --context engineering   # термины: Kafka, а не «кавка»
./voicy hear созвон.opus --hotwords "Helm, Grafana"
TEXT=$(./voicy hear запись.opus)            # stdout чистый, можно подставлять

./voicy music "lo-fi, mellow piano" bed.opus --instrumental --duration 60   # музыка
./voicy music "pop ballad, female vocal" song.opus --lyrics @текст.txt --language ru
./voicy music-models                        # модели музыки: что умеет каждая

./voicy voices                              # какие голоса есть
./voicy status                              # модели, устройство, готовность
```

`./voicy <команда> --help` — остальные флаги.

## Не ждать

Все запросы идут через одну очередь. Длинную работу можно поставить и уйти:

```bash
ID=$(./voicy say @статья.md --detach)       # в stdout только id задания
./voicy job $ID out.opus --wait             # дождаться и забрать звук
ID=$(./voicy hear лекция.opus --detach)
./voicy job $ID --wait --format srt         # расшифровка по id
./voicy jobs                                # что в очереди
./voicy cancel $ID
./voicy say "..." --webhook http://сервис/hook   # сервер сам позовёт, когда готово
```

Задания живут в памяти сервера: 30 минут после готовности и до перезапуска.

## Сервер

```bash
./voicy up          # поднять и прогреть: docker, а если его нет — бинарником на Rust
./voicy up --cpu    # без GPU: работает, но вдвое медленнее реального времени
./voicy down
```

Адрес по умолчанию — `http://localhost:8080`, меняется через `VOICY_URL`;
`up` берёт порт из него же. Если порт занят чужим приложением —
`VOICY_URL=http://localhost:8090 ./voicy up`.

**Docker не обязателен.** Синтез, распознавание и всё остальное — обычные
запросы по HTTP; docker нужен только команде `up`, и та умеет без него.
`./voicy up` сам проверяет, жив ли docker, и молча переходит на бинарник
на Rust. Выбрать явно — `--native` или `--docker` (второй не отступает
на запасной путь, если docker сломан).

Бинарник CLI ищет в `rust/target/release/`, в `VOICY_BIN` и в PATH. Нет —
`--install` соберёт его (нужны Rust, g++ и cmake), а библиотеки и модели
поставит `voicy setup` — без `--install` он спросит, прежде чем качать.
Python серверу не нужен.

```bash
./voicy up --install              # собрать, поставить и запустить
./voicy status                    # в каком состоянии модели и устройство
```

Сервер живёт обычным процессом: pid и журнал — в `~/.cache/voicy/run/`,
останавливается тем же `./voicy down`.

`ffmpeg` нужен только для `aac`: остальные форматы и темп сервер кодирует,
читает и растягивает сам. В образе ffmpeg есть.

## Три вещи, на которых легко споткнуться

**Аудио не пишется в stdout.** Всегда указывайте файл. Если дёргаете HTTP
напрямую — `curl -o out.opus`, иначе бинарь улетит в вывод и засорит контекст.
CLI это запрещает явно.

**Первый вызов долгий, и это не поломка.** Первый запуск качает библиотеки
и модели — около восьми гигабайт, — дальше они лежат в кэше `~/.cache/voicy`
или томе `models`; пока docker качает, сервер ещё не отвечает. После каждого
старта модели грузятся лениво: первый синтез ждёт загрузки Qwen3-TTS (около 9 с),
первое распознавание — Whisper. `./voicy up` прогревает их заранее,
так что дальше вызовы идут в обычном темпе. Таймаут CLI — 30 минут;
не сокращайте его «для надёжности».

**Скорость синтеза — около ×4 на видеокарте** (RTX 3080): минута звука
примерно за 15 секунд. Без видеокарты — примерно вдвое медленнее реального времени.
Длинный текст всё равно удобнее ставить заданием (`--detach`), для живого
разговора — брать синтез потоком: первый звук меньше чем через секунду, а не после
всего ответа.

**Прокси ломает обращение к себе же.** При заданных `HTTP_PROXY`/`HTTPS_PROXY`
клиенты на httpx (включая официальный клиент OpenAI) идут к локальному серверу
через прокси и получают 503. Лечится `NO_PROXY=127.0.0.1,localhost`.
CLI обходит прокси для локальных адресов сам.

## Музыка

Моделей может быть несколько, выбирает запрос: `--model` (список —
`./voicy music-models`, у каждой — что умеет и какая лицензия). Ставятся
отдельно от речи: `voicy setup music` (ACE-Step 1.5, около 5.5 ГБ). Без
`--lyrics` и без `--instrumental` текст напишет сама модель, без
`--duration` — она же выберет длину. Текст песни размечается частями:
`[verse]`, `[chorus]`, `[bridge]`. Музыка — стерео 48 кГц; на RTX 3080 песня
в 75 с считается за 8 с, если веса на быстром диске (с диска Windows из WSL
загрузка частей модели добавляет десятки секунд). Длина с `--duration` — ровно
та, что просили.
Подробности — раздел «Музыка» в [`server/README.md`](server/README.md)
и `docs/adr/0028`.

## Голоса

Два готовых: `turgenev` (118 слов/мин, слитная манера, по умолчанию)
и `dostoevsky` (100 слов/мин, чуть больше пауз). Свой добавляется образцом
на 8–14 секунд с чистой записью и границами по фразе:

```bash
./voicy add-voice образец.wav имя --note "чем хорош"
```

Подойдёт любой формат, хоть запись с телефона: сервер перекодирует образец сам.
Существующее имя не перезаписывается без `--replace`.

Расшифровку писать не нужно — сервер распознает её сам, и это надёжнее ручного
ввода. Расшифровка здесь важнее, чем кажется: тот же клип с текстом, обрезанным
на полуслове, дал 7.3% ошибок против 1.0% при точном совпадении.

## Если текст инженерный

У синтеза есть два расширения сверх контракта OpenAI, оба по умолчанию выключены:

```bash
./voicy say "..." out.opus --prepare   # словарь произношений: 79 терминов
./voicy say "..." out.opus --legato    # убрать запятые внутри коротких фраз
./voicy prepare "API и CI/CD"          # посмотреть, что получится, без синтеза (со знаками ударения)
```

Но главное не в ручках: **листинг нельзя озвучить, его нужно переписать
в объяснение**. `List<? extends Number>` → «лист вайлдкард экстендс Намбер» —
всё ещё листинг, просто прочитанный вслух. Короткие предложения без внутренней
пунктуации слушаются заметно лучше: запятая читается моделью как повод
остановиться. Подробности — `docs/adr/0002` и `docs/adr/0015`.

Темп задаётся `--speed` в диапазоне 0.8–1.2 и делается растяжением готового
звука, а не ручкой модели: у модели замедление роняет разборчивость впятеро
(`docs/adr/0005`).

**Ударения** сервер ставит сам: RUAccent размечает текст, и после ударной
гласной встаёт `U+0301` — модель по умолчанию дообучена этот знак слушать
(`docs/adr/0023`). Отключить — `--no-stress` или `"stress": false`. Чтобы
поправить ударение в слове, впишите знак прямо в текст или в словарь
произношений: `дже́нерики` — готовый знак сервер не трогает. `+` по-прежнему
читается вслух как «плюс», а исходная модель (и движки на Python) знак не понимает
и коверкает слово — поэтому сервер ставит знаки, только если модель объявила
их понимание (`stress.json` рядом с весами).

## Без CLI

API совместимо с аудио-частью OpenAI, так что достаточно сменить базовый адрес:

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8080/v1", api_key="not-needed")
client.audio.speech.create(model="tts-1", voice="turgenev", input="Текст",
                           response_format="opus").stream_to_file("out.opus")
```

```bash
curl -s localhost:8080/v1/audio/speech -H 'Content-Type: application/json' \
  -d '{"input":"текст","voice":"turgenev","response_format":"opus"}' -o out.opus
```

Программе на Rust сервер не нужен вовсе: те же движки встраиваются крейтом
`voicy-core` — `Tts::speak`, `Stt::transcribe_file` и т. д. в своём процессе,
модели из того же кэша (`rust/core/README.md`).

Полный список маршрутов — [`server/README.md`](server/README.md): задания,
очередь и webhook (`/v1/jobs`), расшифровка с `stream=true`, профили контекста
(`/v1/contexts`) и голосовой агент по WebSocket: живая речь
(`/v1/audio/transcriptions/stream`) — начало речи, текст по предложениям
и конец реплики по интонации; синтез потоком (`/v1/audio/speech/stream`) —
текст токенами LLM на входе, звук по кускам на выходе, отмена при перебивании.

Если сервер запущен с `VOICY_API_KEY`, тот же ключ нужен клиенту: CLI берёт его
из переменной сам, клиенту OpenAI — `api_key=`, curl — `-H "Authorization: Bearer $VOICY_API_KEY"`.
Ошибки приходят в формате OpenAI: `{"error": {"message": ...}}`.

За nginx или другим обратным прокси сервер требует настройки: без неё
отваливаются WebSocket, загрузка больших файлов и долгий синтез, а ссылки
в webhook ведут на внутренний адрес. Проверенный конфиг и `VOICY_PUBLIC_URL` —
в разделе «За обратным прокси» [`server/README.md`](server/README.md).

## Где что лежит

```
voicy         этот CLI
rust/         сам сервер, один бинарник: маршруты, очередь, движки в процессе
server/       что сервер берёт из репозитория: engines/ — движки на Python,
              static/ — консоль, voices/ и contexts/ — голоса и профили
data/         исходные тексты экспериментов
rust/core/    движки как библиотека; assets/ — словарь произношений и голоса
docs/adr/     почему сделано именно так — читать до того, как менять поведение
experiments/  что пробовали и чем мерили; results/ — сырые замеры
article/      итоговая статья со всем аудио
```

Порождённое аудио в репозиторий не кладётся: `*.wav` в `.gitignore`, исключение —
референсные голоса сервера. Готовые файлы пишите во временный каталог.
