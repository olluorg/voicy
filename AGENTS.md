# voicy для агента

Локальный синтез и распознавание речи. Ключей нет, сеть не нужна,
всё исполняется на этой машине.

**Озвучить текст — одна команда:**

```bash
./voicy say "Текст, который нужно озвучить" out.opus
```

В stdout уходит путь к файлу, в stderr — сколько получилось звука и за сколько.
Сервер не поднят — `./voicy up` (см. ниже).

## Что нужно чаще всего

```bash
./voicy say "текст" out.opus                # синтез
./voicy say @статья.md out.opus             # текст из файла
cat статья.md | ./voicy say - out.opus      # или из потока
./voicy say "текст" out.opus --voice dostoevsky --speed 0.9

./voicy hear запись.opus                    # распознавание → текст в stdout
./voicy hear запись.opus --format srt       # субтитры
TEXT=$(./voicy hear запись.opus)            # stdout чистый, можно подставлять

./voicy voices                              # какие голоса есть
./voicy status                              # модели, устройство, готовность
```

`./voicy <команда> --help` — остальные флаги.

## Сервер

```bash
./voicy up          # docker compose up -d, ждёт готовности и прогревает модели
./voicy up --cpu    # без GPU: работает, но медленнее реального времени
./voicy down
```

Адрес по умолчанию — `http://localhost:8080`, меняется через `VOICY_URL`.
Если порт занят чужим приложением, CLI скажет об этом прямо:
`VOICY_PORT=8090 ./voicy up` и дальше `VOICY_URL=http://localhost:8090`.

## Три вещи, на которых легко споткнуться

**Аудио не пишется в stdout.** Всегда указывайте файл. Если дёргаете HTTP
напрямую — `curl -o out.opus`, иначе бинарь улетит в вывод и засорит контекст.
CLI это запрещает явно.

**Первый вызов долгий, и это не поломка.** Первый запуск сервера качает около
пяти гигабайт весов, дальше они лежат в томе `models`. После каждого старта
модели грузятся лениво: первый синтез ждёт загрузки Qwen3-TTS (~3.5 ГБ),
первое распознавание — Whisper (~1.5 ГБ). `./voicy up` прогревает их заранее,
так что дальше вызовы идут в обычном темпе. Таймаут CLI — 30 минут;
не сокращайте его «для надёжности».

**Прокси ломает обращение к себе же.** При заданных `HTTP_PROXY`/`HTTPS_PROXY`
клиенты на httpx (включая официальный клиент OpenAI) идут к локальному серверу
через прокси и получают 503. Лечится `NO_PROXY=127.0.0.1,localhost`.
CLI обходит прокси для локальных адресов сам.

## Голоса

Два готовых: `turgenev` (118 слов/мин, слитная манера, по умолчанию)
и `dostoevsky` (100 слов/мин, чуть больше пауз). Свой добавляется образцом
на 8–14 секунд с чистой записью и границами по фразе:

```bash
./voicy add-voice образец.wav имя --note "чем хорош"
```

Расшифровку писать не нужно — сервер распознает её сам, и это надёжнее ручного
ввода. Расшифровка здесь важнее, чем кажется: тот же клип с текстом, обрезанным
на полуслове, дал 7.3% ошибок против 1.0% при точном совпадении.

## Если текст инженерный

У синтеза есть два расширения сверх контракта OpenAI, оба по умолчанию выключены:

```bash
./voicy say "..." out.opus --prepare   # словарь произношений: 79 терминов
./voicy say "..." out.opus --legato    # убрать запятые внутри коротких фраз
./voicy prepare "API и CI/CD"          # посмотреть, что получится, без синтеза
```

Но главное не в ручках: **листинг нельзя озвучить, его нужно переписать
в объяснение**. `List<? extends Number>` → «лист вайлдкард экстендс Намбер» —
всё ещё листинг, просто прочитанный вслух. Короткие предложения без внутренней
пунктуации слушаются заметно лучше: запятая читается моделью как повод
остановиться. Подробности — `docs/adr/0002` и `docs/adr/0015`.

Темп задаётся `--speed` в диапазоне 0.8–1.2 и делается растяжением готового
звука, а не ручкой модели: у модели замедление роняет разборчивость впятеро
(`docs/adr/0005`). Ударениями Qwen3-TTS управляют только выбором слов —
`+` он произносит вслух как «плюс», диакритика коверкает слово.

## Без CLI

API совместимо с аудио-частью OpenAI, так что достаточно сменить базовый адрес:

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8080/v1", api_key="not-needed")
client.audio.speech.create(model="tts-1", voice="turgenev", input="Текст",
                           response_format="opus").stream_to_file("out.opus")
```

```bash
curl -s localhost:8080/v1/audio/speech -H 'Content-Type: application/json' \
  -d '{"input":"текст","voice":"turgenev","response_format":"opus"}' -o out.opus
```

Полный список маршрутов, включая задания с прогрессом
(`/v1/jobs/speech` + поток событий) — [`server/README.md`](server/README.md).

## Где что лежит

```
voicy         этот CLI
server/       сам сервер: app.py — маршруты, engines/ — модели, static/ — консоль
data/         исходные тексты и словарь произношений
docs/adr/     почему сделано именно так — читать до того, как менять поведение
experiments/  что пробовали и чем мерили; results/ — сырые замеры
article/      итоговая статья со всем аудио
```

Порождённое аудио в репозиторий не кладётся: `*.wav` в `.gitignore`, исключение —
референсные голоса сервера. Готовые файлы пишите во временный каталог.
